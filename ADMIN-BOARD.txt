Admin-Board der Reeder Software GmbH (Phase 1)
==============================================

Starten (im Ordner "Website R S GmbH"):

    npm start

Dann im Browser:
    Website:      http://localhost:5510
    Admin-Board:  http://localhost:5510/admin

Anmeldung
- Ihre ersten Zugangsdaten stehen in der Datei .env (ADMIN_EMAIL / ADMIN_PASSWORD).
- Bitte nach der ersten Anmeldung unter "Einstellungen" ein eigenes Passwort setzen.

Was das Board kann
- Übersicht: neue Anfragen und die nächsten Termine.
- Termine: Anfragen bestätigen, absagen oder als erledigt markieren – auf Wunsch mit
  automatischer E-Mail an den Kunden (bei Bestätigung inkl. Kalendereintrag im Anhang).
  Neue Anfragen blockieren den Zeitraum sofort, damit niemand doppelt bucht.
- Projektanfragen: Status (neu, in Bearbeitung, Angebot, gewonnen …) und interne Notizen.
- Verfügbarkeit: Arbeitszeiten je Wochentag, Dauer und Puffer je Termintyp, Vorlauf,
  wie weit im Voraus gebucht werden kann, Urlaub und Sperrtage. Die Website zeigt
  Änderungen sofort an.
- Einstellungen: Absender der E-Mails, Kalender-Abo-Adresse für Outlook/Google/iPhone,
  Passwort ändern, Postausgang aller E-Mails.

E-Mail-Versand einschalten
- In der Datei .env die SMTP-Angaben Ihres Postfachs eintragen (siehe .env.example):
  SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS – und den Server neu starten.
- Bis dahin werden alle E-Mails nur im Postausgang gespeichert.

Daten
- Alles liegt lokal in data/reeder.db. Für eine Sicherung den Ordner "data" kopieren.
- .env und data/ niemals veröffentlichen (der Server gibt sie auch nicht heraus).

Ohne Server
- Öffnet man die HTML-Dateien direkt, funktioniert die Website im Vorschau-Modus
  (Beispielzeiten, Anfragen per E-Mail-Programm).

KUNDENPORTAL (Chat & Prototypen)
--------------------------------
Kundenadresse:  http://localhost:5510/portal/   (später: https://www.reeder-software.de/portal/)

1. Admin-Board → "Kunden & Chat" → "Neuer Kunde": Firma, Ansprechpartner, E-Mail.
   Der Kunde bekommt einen Einladungslink (14 Tage gültig) und legt damit selbst sein Passwort fest.
   Solange der E-Mail-Versand nicht eingerichtet ist: Link kopieren und selbst verschicken.
2. Chat: Nachrichten erscheinen nach wenigen Sekunden auf beiden Seiten. Bei neuen Nachrichten
   geht höchstens alle 30 Minuten eine Benachrichtigungs-Mail raus (an den Kunden bzw. an Sie).
3. Prototypen: beim Kunden → Reiter "Prototypen" → HTML-Datei, Ordner oder ZIP hineinziehen.
   Die Startseite wird automatisch erkannt (index.html). Optional im Chat ankündigen.
   Der Kunde klickt sich im Browser durch – Ansicht Desktop / Tablet / Smartphone.
   Prototypen laufen abgeschottet: Eingaben werden nicht gespeichert, kein Zugriff auf Logins.
   "Link" kopiert eine direkte Adresse – jeder mit diesem Link kann den Prototyp ansehen.
   Deaktivieren macht den Link sofort ungültig; Löschen entfernt die Dateien.
4. "Zugang sperren" meldet den Kunden sofort ab. "Neuer Zugangslink" hilft bei vergessenem Passwort.

Gespeichert wird alles lokal: data/reeder.db und data/prototypes/.

PROJEKTRÄUME (Projekte, Termine, Finanzen, Dokumente, Anmerkungen)
------------------------------------------------------------------
Beim Kunden gibt es die Reiter: Chat · Projekte · Anmerkungen · Termine · Dokumente.

Projekte: Titel, Art, Modell, Phase (Erstgespräch → Konzept → Prototyp → Umsetzung → Launch → Betreuung),
  Kostenvoranschlag netto (brutto wird mit der USt. automatisch berechnet), vereinbarte Konditionen,
  Zahlungsplan (Positionen netto, Fälligkeit, Haken "bezahlt"). Alles davon sieht der Kunde sofort.
  Jede Änderung (Phase, Zahlung eingegangen, neues Dokument, neue Version …) landet im Verlauf.
Prototypen: im Projekt hochladen. "Neue Version" legt V2, V3 … an – ältere Versionen bleiben abrufbar.
  Unter "Was hat sich geändert?" kurz notieren, was neu ist.
Anmerkungen: Kunden zeichnen im Prototyp mit Stift/Textmarker oder setzen einen Kommentar-Punkt.
  Reiter "Anmerkungen" = Liste zum Abarbeiten. "Zur Stelle →" öffnet genau die Seite, Breite und Position.
  Mit "✓ Erledigt" abhaken. Sie können im Viewer auch selbst anmerken.
Termine: mit Zusammenfassung und nächsten Schritten (sieht der Kunde). Buchungen über die Website
  mit derselben E-Mail-Adresse erscheinen dort zum Übernehmen.
Dokumente: Angebote, Rechnungen, Verträge (PDF, Bilder, Office) mit Betrag und Datum hochladen.

Passwort vergessen/ändern: Einstellungen → Passwort ändern, oder neues Passwort in .env eintragen
  und "npm run passwort" ausführen.

AUTOMATIK: KUNDE WIRD INFORMIERT
--------------------------------
Jeder Meilenstein (Projekt gestartet, Angebot übersendet, Rechnung gestellt, Zahlungseingang bestätigt,
Termin vereinbart, Zusammenfassung hinterlegt, Prototyp/Version veröffentlicht, Phasenwechsel)
1. steht sofort im Portal des Kunden (Verlauf + Übersicht),
2. löst eine E-Mail aus. Änderungen innerhalb von 90 Sekunden werden zu EINER Mail gebündelt.
Ohne Mail speichern: Haken "Kunden per E-Mail informieren" entfernen.
Der Kunde kann diese Mails im Portal unter Konto abschalten.

Rechnung hochladen: Dokumente → Hochladen → Art "Rechnung", Projekt wählen → "Zu welcher Zahlung gehört
die Rechnung?" (die nächste offene Position ist vorausgewählt, Betrag wird übernommen).
Die Zahlung springt beim Kunden auf "Rechnung gestellt" mit Link zur PDF.
Geld eingegangen: im Projekt beim Zahlungsplan Status "bezahlt" wählen → Speichern.

TERMINANFRAGEN VON BESTANDSKUNDEN
---------------------------------
Im Portal unter Termine (und im Projekt / bei "Ihr Ansprechpartner") gibt es "Termin anfragen".
Terminarten nur für Kunden: Projekt-Abstimmung, Feedback zum Prototyp, Kurze Rückfrage, Schulung & Einweisung
(Dauer/Puffer/aktiv unter Verfügbarkeit, markiert mit "nur Kundenportal"; auf der Website nicht buchbar).
Der Kunde wählt bis zu 3 Wunschtermine aus Ihren freien Zeiten oder "flexibel" + Nachricht.
Sie bekommen eine Mail, die Anfrage steht im Chat und beim Kunden im Reiter "Termine" (Badge 📅).
"Annehmen" bei einem Wunschtermin → Termin im Kalender (blockiert die Zeit, Kalender-Abo), im Portal,
im Verlauf, Bestätigung im Chat + Mail. "Andere Zeit …" bestätigt eine eigene Zeit, "Ablehnen" schickt
Ihre Antwort in den Chat.

BOARD FÜR INHABER UND ENTWICKLER (Phase 1)
------------------------------------------
Navigation: Cockpit · Posteingang · Kunden · Projekte · Termine · Vertrieb · Team · Einstellungen
- Cockpit: "Heute zu tun", Termine, Projekte nach Phase; als Inhaber zusätzlich offene Forderungen und Eingänge.
- Posteingang: alle ungelesenen Chats, Terminanfragen, offenen Anmerkungen, Website-Buchungen und
  Projektanfragen an einem Ort – ein Klick führt direkt hin.
- Projekte: Board nach Phase über alle Kunden; Klick öffnet das Projekt.
- Team: Personen einladen (Rolle Inhaber oder Entwickler), Projekte zuweisen, sperren.
  Entwickler sehen NUR zugewiesene Projekte – ohne Beträge, Zahlungen, Rechnungen, Verträge,
  ohne Vertrieb, Team und Einstellungen. Das prüft der Server, nicht nur die Oberfläche.
  Zuweisen geht auch direkt im Projekt (Feld "Team").
- Einstellungen: Unternehmensdaten (für Rechnungen), E-Mail-Postfach (SMTP) direkt im Board inkl.
  Testmail, Absender, Postausgang, Kalender-Abo, eigenes Passwort.

FINANZEN (Phase 2, nur Inhaber)
-------------------------------
Board → Finanzen: Übersicht · Rechnungen · Angebote · Belege · Auswertung & Export
Einmalig vorher: Einstellungen → Unternehmen (Anschrift, Steuernummer/USt-IdNr., IBAN, Zahlungsziel,
Versteuerung Soll/Ist, DATEV-Berater-/Mandantennummer) und beim Kunden "Rechnungsadresse".
- Rechnung: "Neue Rechnung" oder im Projekt beim Zahlungsplan "+ RE". Entwürfe sind frei änderbar,
  "Vorschau (PDF)" zeigt das Ergebnis. "Festschreiben & senden": fortlaufende Nummer RE-JJJJ-00001,
  PDF nach § 14 UStG, Mail mit PDF an den Kunden, PDF im Kundenportal, Zahlungsposition "Rechnung gestellt".
  Danach unveränderlich (GoBD) – Korrektur nur per "Stornieren" (Stornorechnung ST-JJJJ-…).
- Zahlung eingegangen → Rechnung und Zahlungsplan "bezahlt", Kunde wird informiert.
- Überfällig: Board schlägt Zahlungserinnerung → 1./2./3. Mahnung vor (14/28/42 Tage), Versand per Klick.
- Angebote: AN-JJJJ-…, angenommen/abgelehnt, "In Rechnung übernehmen".
- Belege: PDF/Foto/E-Rechnung hochladen, Kategorie (mit SKR04-Konto), Steuer (19/7/0 %, Reverse Charge § 13b).
  Nach Monatsende "Monat abschließen" → Belege festgeschrieben.
- Auswertung: Umsatz, Ausgaben, Umsatzsteuer-Zahllast je Monat/Quartal/Jahr, Protokoll aller Vorgänge.
  "ZIP herunterladen" = Paket für den Steuerberater (Rechnungsbuch, Belege, USt, DATEV-Buchungsstapel, PDFs).
  Kontenzuordnung und DATEV-Stapel einmal mit dem Steuerberater abstimmen.
Dateien: data/finance/ (PDFs, Belege – werden nie überschrieben).

KUNDENPROZESS: ANFRAGE → INTERESSENT → MANDANT
----------------------------------------------
1. Jede Website-Buchung und Projektanfrage legt automatisch einen Kontakt an (Status "Anfrage", ohne Portal).
2. Posteingang: direkt in der Zeile bestätigen / ablehnen / antworten / Erstgespräch vereinbaren.
   Bestätigen schickt die Einladung mit Video-Link (Jitsi, ohne Konto) + Kalenderdatei; Status → "Interessent".
   Fester Video-Raum (Teams/Zoom/Meet) statt Jitsi: Einstellungen → Termine & Video.
3. Kunden → Kontakt → "Termin vereinbaren": freie Zeit wählen, Einladung geht automatisch raus.
4. Nach dem Gespräch "Zum Mandanten machen" → Portal-Einladung; dann Projekt, Angebot, Rechnung.
   Überblick zeigt den kompletten Verlauf und den nächsten sinnvollen Schritt.
Kunden-Liste: Filter Alle / Anfragen / Interessenten / Mandanten / Archiv + Suche. Entwickler sehen nur Mandanten.
Projekte: Liste mit Filter nach Phase, Suche, Sortierung ("Braucht Aufmerksamkeit", "Nächster Termin" …).

-----------------------------------------

- Projekte: oben die Auslastung je Person (Klick filtert), Filter nach Phase, Person, Art, Modell. Klick auf ein Projekt = eigene Projektseite (Phase per Klick setzen, Team, Auftrag & Zahlungen, Prototypen mit offenen Anmerkungen, Termine, Dokumente, Verlauf).

KALENDER, VERTRIEB, POSTEINGANG (Stand 12.11.2026)
--------------------------------------------------

AUTOMATIK (Baustein A, 12.11.2026)
----------------------------------
- Das Board prueft jede Minute: Terminerinnerungen an Kunden (24 Std. und 1 Std. vorher), Nachfass-Mail bei Projektanfragen ohne Termin, Vorschlaege im Cockpit (unbestaetigte Website-Termine, Angebote ohne Antwort, Mahnstufen, fehlende Zusammenfassungen, ruhende Projekte), Wochenbericht montags 7 Uhr an alle Inhaber.
- Jede E-Mail geht nur einmal raus und steht im Protokoll (Einstellungen > Automatik) sowie im Verlauf des Kunden.
- Alles einzeln ab- und einstellbar unter Einstellungen > Automatik. Abschalten fuer Tests: AUTOMATION_DISABLED=1.

ANGEBOT -> VERTRAG -> RECHNUNG (Baustein B, 13.11.2026)
-------------------------------------------------------
- Angebot erstellen (Finanzen oder Kundenakte > Neues Angebot): unten "Zahlungsplan & Vertrag" mit Raten in Prozent und "faellig bei Auftrag / ab Phase ...", optional Haken AVV. Der Plan muss 100 % ergeben.
- Nach dem Festschreiben sieht der Kunde das Angebot im Portal (Banner in der Uebersicht und im Projekt unter "Angebot & Zahlungen") und kann es verbindlich annehmen: Name, optional Funktion, Haken fuer Berechtigung, Vertragsbedingungen und ggf. AVV. Fehlt die Rechnungsanschrift, fragt das Portal sie gleich mit ab. Ablehnen mit Begruendung ist ebenfalls moeglich.
- Bei Annahme passiert automatisch: Kunde wird Mandant, Projekt wird angelegt bzw. aktualisiert (Auftragswert, Konditionen, Phase Konzept), Zahlungsplan wird uebernommen, Auftragsbestaetigung als PDF (mit Nachweis: Name, Zeitpunkt, IP, Fassung und Pruefsummen der Bedingungen) liegt beim Kunden unter Dokumente und geht per Mail raus, Danke-Nachricht im Chat, Mail an die Inhaber.
- Die Automatik legt jede Rate als Rechnungsentwurf an, sobald sie faellig ist (bei Auftrag sofort, sonst wenn das Projekt die Phase erreicht). Im Cockpit erscheint "Rechnung freigeben" -> "Freigeben & senden" schreibt fest und schickt die Rechnung mit PDF. Ausserdem: "Neuer Auftrag - Team zuweisen" und "Angebot abgelehnt" zum Nachfragen.
- Zusage per Telefon/E-Mail: im Angebot "Zusage ausserhalb des Portals" -> gleicher Ablauf, der Nachweis vermerkt den Weg.
- Einstellungen > Vertrag & AVV: Standard-Zahlungsplan, Vertragsbedingungen, AVV. Jede Textaenderung wird als neue Fassung gespeichert; angenommene Angebote behalten ihre Fassung. Der Annahme-Nachweis ist in der Datenbank unveraenderlich.
- WICHTIG: Die Vertragstexte sind ein Entwurf und muessen vor dem ersten echten Auftrag anwaltlich geprueft werden.
- Demo: Malerbetrieb Sommer hat ein offenes Angebot AN-2026-00005 "Sommer Planer - Vollversion" zum Ausprobieren (Login des Testkunden in .env: DEMO_MVP_KUNDE_*).

SOFTWARE & VERTRAEGE (Baustein C, 13.11.2026)
---------------------------------------------
- Neuer Bereich "Software & Vertraege" im Board mit drei Reitern: Uebersicht, Vertraege, Produkte.
- Uebersicht (nur Inhaber): MRR (wiederkehrender Umsatz netto pro Monat), ARR, Anzahl Vertraege/Kunden, Verlauf der letzten 12 Monate, Aufteilung nach Art und Produkt, Kuendigungsfristen der naechsten 60 Tage, gekuendigte Vertraege, Signature-Kaufoptionen mit angerechnetem Betrag.
- Vertraege: laufende Vertraege (IT-Betreuung, Signature-Lizenz, Produkt-Lizenz, Hosting, Wartung, KI-Telefonassistent ...) mit Monatsbetrag, Abrechnungsintervall, Mindestlaufzeit, Verlaengerung, Kuendigungsfrist. Anlegen ueber "Neuer Vertrag", in der Kundenakte oder auf der Projektseite unter "Mehr > Laufenden Vertrag anlegen".
- Reeder Signature: Kaufpreis, Anrechnung in Prozent (Standard 50 %) und "schon gezahlt vor dem Board" fuer Altvertraege. Angerechnet wird der Anteil aller bezahlten Rechnungen des Vertrags; Kaufoption ab Ende der Mindestlaufzeit.
- Abrechnung: Zum Termin "naechste Rechnung" legt die Automatik einen Rechnungsentwurf fuer den Leistungszeitraum an; im Cockpit "Freigeben & senden". Kuendigung erfassen berechnet das fruehestmoegliche Ende; bis dahin wird weiter abgerechnet, danach endet der Vertrag automatisch.
- Cockpit-Hinweise: Kuendigungsfrist endet bald (Gespraech fuehren), gekuendigter Vertrag laeuft aus, Signature-Kaufoption beginnt. Einstellbar unter Einstellungen > Automatik. Der Wochenbericht enthaelt den MRR.
- Produkte: eigene Produkte (Status, Fortschritt, Version, naechster Meilenstein, Verantwortliche) und Leistungen/Pakete mit Listenpreis. Entwickler sehen die Produkte ohne Betraege, aber keine Vertraege.
- Kundenportal: Kunden mit Vertraegen sehen den Menuepunkt "Vertraege" mit Betrag, Laufzeit, Kuendigungsfrist und bei Signature dem angerechneten Betrag und Restkaufpreis.
- Demo: 8 Produkte/Leistungen und 12 Beispielvertraege (MRR 2.615 EUR) sind im Demo-Board angelegt. Im echten Board ist nichts angelegt.

AUFGABEN & ZEITERFASSUNG - MEIN ARBEITSPLATZ (Baustein D, 13.11.2026)
---------------------------------------------------------------------
- "Mein Arbeitsplatz" (neuer Menuepunkt, fuer Entwickler die Startseite): Stoppuhr, eigene Aufgaben nach Faelligkeit (ueberfaellig / heute / diese Woche / spaeter), Stunden der Woche, eigene Projekte mit offenen Aufgaben und Kunden-Anmerkungen, Termine der naechsten 7 Tage, eigene Zeiteintraege der letzten 14 Tage.
- Inhaber sehen dort zusaetzlich "Team diese Woche" (Stunden je Person, offene und ueberfaellige Aufgaben, wer gerade an was arbeitet), Aufgaben ohne Zustaendigkeit und "Auswertung & CSV-Export" der Zeiten.
- Stoppuhr: Projekt waehlen oder bei einer Aufgabe auf ▶ klicken -> laeuft; "Stoppen & speichern" legt den Zeiteintrag an. Eine laufende Stoppuhr zeigt einen gruenen Punkt im Menue. Laeuft sie ueber 12 Std., wird auf 12 Std. begrenzt und markiert.
- Zeit nachtragen: Dauer als 1:30, 1,5 oder 45 (Minuten).
- Projektseite: Karte "Aufgaben" (schnell anlegen mit Enter, abhaken, Details mit Zustaendigkeit, Prioritaet, Faelligkeit, Schaetzung) und Karte "Zeit" (erfasst gesamt, Schaetzung; fuer Inhaber Stunden je Person und - ab Phase Launch - der effektive Stundensatz).
- Kunden-Anmerkung -> "→ Aufgabe": wird die Aufgabe erledigt, ist auch die Anmerkung erledigt (der Kunde sieht den Haken im Portal).
- Termin mit "Naechsten Schritten" -> "→ Aufgaben": jede Zeile wird eine Aufgabe (nichts doppelt).
- Sichtbarkeit: Entwickler sehen ihre eigenen Zeiten und die Projektsumme, Inhaber alles. Ueberfaellige Aufgaben erscheinen im Cockpit bei der zustaendigen Person (Einstellungen > Automatik). Der Wochenbericht zeigt erfasste Stunden und erledigte Aufgaben je Person.
- Demo: 64 Beispielaufgaben, 3 Wochen Zeiten fuer Lena, Jonas und Mehmet; bei Jonas laeuft gerade die Stoppuhr.

KENNZAHLEN (Baustein E, 13.11.2026)
-----------------------------------
- Neuer Menuepunkt "Kennzahlen" (nur Inhaber). Zeitraum oben waehlbar: dieser Monat / dieses Quartal / dieses Jahr. Verglichen wird immer mit dem gleich langen Abschnitt der Vorperiode (z. B. 1.-13. Oktober gegen 1.-13. November).
- "Worauf achten": automatisch abgeleitete Hinweise mit Stufe (Kritisch / Achtung / Hinweis / Gut), jeweils mit Klick zur passenden Stelle: ueberfaellige Rechnungen, Rechnungen zur Freigabe, Ueberlastung oder freie Kapazitaet im Team, Projekte mit Risiko, Klumpenrisiko (ein Kunde > 35 % vom Umsatz), niedrige Gewinnquote, weniger Anfragen, wachsender Umsatz/MRR.
- Geld: Umsatz netto, Zahlungseingang, Ergebnis (Umsatz - Ausgaben), offene und ueberfaellige Forderungen, MRR/ARR, Auftragsbestand; Umsatz & Ausgaben der letzten 12 Monate; erwartete Eingaenge in 30/60/90 Tagen.
- Vertrieb: neue Anfragen, gefuehrte Erstgespraeche, neue Auftraege, offene Angebote, Gewinnquote (12 Monate), Anteil Anfrage -> Kunde und Dauer bis zum Projekt; Anfragen pro Monat; MRR-Verlauf.
- Projekte & Team: aktive Projekte nach Phase, erfasste Stunden, Umsatz je Stunde, erledigte Aufgaben; Auslastung je Person (Soll 8 Std. je Arbeitstag, gerechnet ab Beginn der Zeiterfassung); Projekte mit Risiko (Schaetzung um mehr als 20 % ueberschritten, mehrere ueberfaellige Aufgaben, viele offene Kunden-Anmerkungen, kein Team, 14 Tage ohne Bewegung).
- Kunden: wichtigste Kunden der letzten 12 Monate (Rechnungen + Vertraege aufs Jahr), Kundenstamm.
- Hinweis: "Neue Auftraege" zaehlt Projekte mit Auftragswert, die im Zeitraum angelegt wurden. Die Diagramme zeigen beim Darueberfahren die genauen Werte.

SUPPORT & BETRIEB (Baustein F, 13.11.2026)
------------------------------------------
- Kundenportal > "Support": Kunden melden Fehler, Fragen oder Aenderungswuensche, waehlen das Projekt und die Dringlichkeit (Normal / Hoch / Kritisch - System steht) und sehen dabei die zugesagte Antwortzeit. Verlauf, Antworten, "Problem geloest", wieder oeffnen.
- Board > "Support" (Menuepunkt mit Zahl ungelesener Kundenantworten): Liste nach Status und Zustaendigkeit, mit Frist-Anzeige ("Antwort in 3 Std." / "2 Std. ueber der Frist"). In der Anfrage: antworten (geht per Mail an den Kunden), interne Notiz (Kunde sieht sie nicht), "Senden & auf Kunde warten", "Senden & geloest", Status/Dringlichkeit/Zustaendig/Projekt aendern, "→ Aufgabe", Zeit erfassen, Stoppuhr.
- Zustaendig ist automatisch, wer im Projekt arbeitet. Neue Anfragen gehen per Mail an Inhaber und Zustaendige; Entwickler sehen nur Anfragen ihrer Projekte.
- Reaktionszeiten (Einstellungen > Betrieb): Standard Kritisch 4 Std. rund um die Uhr, Hoch 1 Werktag, Normal 2 Werktage (Geschaeftszeit Mo-Fr 9-17 Uhr). Cockpit-Hinweis, wenn die Frist knapp oder ueberschritten ist. "Wartet auf Kunde" -> nach 4 Tagen freundliche Erinnerung an den Kunden; "Geloest" -> nach 7 Tagen automatisch geschlossen.
- Kennzahlen und Wochenbericht zeigen offene Anfragen, Durchschnitt bis zur ersten Antwort und eingehaltene Fristen.
- Einstellungen > Betrieb: Systemstatus (Datensicherung, E-Mail, Automatik, Kundensysteme), Datensicherung (jede Nacht nach 2 Uhr bzw. beim Start, 14 Stueck vorgehalten, Download, "Jetzt sichern"; gesichert wird die Datenbank in data/backups - Dokumente/Belege/Prototypen liegen als Dateien im Datenordner und muessen beim Server-Umzug zusaetzlich gesichert werden), Erreichbarkeit von Kundensystemen (Adresse eintragen, Pruefung alle 5 Minuten, bei Ausfall Cockpit-Hinweis + Mail, bei Wiederherstellung Entwarnung, Verfuegbarkeit der letzten 30 Tage).
- Demo: 6 Beispiel-Anfragen (u. a. eine ueberfaellige, eine kritische) und zwei lokale Ueberwachungen (eine absichtlich offline).

SOFTWARE UND HARDWARE IN EINEM BOARD
------------------------------------
Es gibt nur ein Board und eine Projektliste. Jedes Projekt hat einen Bereich (Software oder Hardware),
der beim Anlegen unter "Neues Projekt" gewählt wird. Ein kleines Schild zeigt ihn überall an:
- Projekte: Schild je Zeile, Filter "Bereich" über der Liste.
- Kunden: Schilder zeigen, ob ein Kunde Software-Projekte, Hardware-Projekte oder beides hat.
- Termine: Kürzel SW oder HW an jedem Termin, der zu einem Projekt gehört.
Ein Hardware-Projekt öffnet seine eigene Seite mit dem Konzept in sechs Schritten (Anforderungen,
Varianten, Module, 3D-Modell, Einkauf & Bau, Prüfung). Eigene Produktideen ohne Auftraggeber
laufen unter dem Kunden "Reeder intern".

Technik
- Schnittstelle: server/hardware.mjs (/api/admin/hardware/...). Der Bereich steht in projects.bereich.
- Oberfläche der Hardware-Seite: admin/hardware/hardware.js und hardware.css. Diese beiden Dateien werden
  gebaut, nicht von Hand bearbeiten. Quelltext und Anleitung: ../Reeder Hardware GmbH/konzept-studio (CLAUDE.md).
- Schilder und Adressen: bereichTag, bereicheTags, bereichKurz, projektHref in admin/admin.js.
- Daten: data/hardware/<Projekt-ID>/projekt.json (das Konzept) und .../dateien/ (Uploads).
- Stand vor dem Einbau: Ordner _sicherung-2026-11-25/ (Server- und Board-Dateien, Datenbank).

Terminarten für Hardware
- "Kostenloses Erstgespräch Hardware" (30 Min) und "Entwicklungskonzept anfragen" (45 Min), beide kostenlos.
  Festgelegt in server/db.mjs (DEFAULT_AVAILABILITY, Kennzeichen bereich: "hardware"); Dauer, Puffer und
  aktiv/inaktiv sind im Board unter Termine > Arbeitszeiten einstellbar.
- Auf der Website: _build/termin.body.html, danach "python _build/build.py ." ausführen.
- Gebuchte Termine tragen im Kalender automatisch das Kürzel HW bzw. SW.


MIT CLAUDE AUSARBEITEN (Hardware-Projekte)
------------------------------------------
Jedes Hardware-Projekt hat einen Arbeitsordner unter "Reeder Hardware GmbH/Projekte/<Projektname>/"
(neben dem Website-Ordner; Demo-Board und Server im Internet nutzen stattdessen DATA_DIR/hardware,
mit HARDWARE_PROJEKTE_DIR lässt sich der Ort festlegen). Darin liegen projekt.json (Konzept),
dateien/ (Unterlagen), notizen/, ergebnisse/ und CLAUDE.md (Anleitung, schreibt das Board selbst).
- "Ordner öffnen" oben rechts im Projekt öffnet ihn im Explorer.
- "In Claude öffnen" legt den Ordner an und öffnet Claude Code darin; der Auftrag steht schon im
  Eingabefeld und wird mit Enter abgeschickt. Das läuft über das eigene Claude-Abo.
Voraussetzung: Claude Code ist als Terminalprogramm installiert (npm install -g @anthropic-ai/claude-code)
und angemeldet. Das Board ruft die Programmdatei direkt auf (claude --handle-uri ...), sucht sie im Pfad und
im npm-Ordner des Benutzers und verwechselt sie nicht mit der Desktop-App. Beides geht nur, wenn Board und
Browser auf demselben Rechner laufen. Das Board dafür im eigenen Terminal starten (npm start).
